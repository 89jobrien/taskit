# First Workspace

Taskit can run without configuration. From a Cargo workspace, start with:

```bash
taskit check quick
```

This checks affected crates relative to `origin/main`, uses offline test filtering when configured,
and runs formatting, linting, compile-tests, and tests.

## Generate workspace files

```bash
taskit init
```

Initialization reads `cargo metadata --no-deps`, discovers packages and local dependencies, and
writes the conventional taskit project files:

```text
taskit.toml
Cruxfile
.cargo/config.toml
.githooks/pre-commit
.githooks/pre-push
.github/workflows/ci.yml
deny.toml
.ctx/
docs/
```

The `.cargo/config.toml` file adds a `cargo taskit` alias. Isolated `xtask/` scaffolding is not
generated by default.

If `taskit.toml` already exists, initialization stops unless overwrite is explicit:

```bash
taskit init --force
```

`--force` is global to initialization: it can overwrite the Cruxfile, hooks, CI workflow,
generated mdBook pages, and other selected scaffold outputs as well as `taskit.toml`.

Use prompts to select optional scaffold components:

```bash
taskit init --interactive
```

Use global dry-run to inspect intended writes without creating files:

```bash
taskit --dry-run init
```

> Current scaffolds contain legacy flat command spellings. Review the generated Cruxfile, hooks,
> CI workflow, docs, and optional xtask adapter. Replace `taskit fmt`, `lint`, `test`, `self-check`,
> `ci`, `pre-commit`, and `pre-push` with their grouped CLI equivalents. The generated
> `cargo taskit` alias also assumes the initialized workspace contains a local package named
> `taskit`; otherwise, use the installed binary directly.

## Run the first checks

```bash
taskit check quick
taskit check ci
taskit health check --update
taskit protocol drift --update
```

The two update commands write `.health-baseline.json` and `taskit-protocol.lock`. Review those
files before committing them.
