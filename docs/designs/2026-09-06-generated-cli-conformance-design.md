# Design: Generated CLI Conformance

## Goal

Ensure every hook, xtask, workflow, Cruxfile, and checked-in command example generated by taskit uses a command accepted by the current clap tree.

## Approved Approach

Correct the generated nested command paths first, then use the root clap parser as the conformance oracle so future CLI migrations cannot silently break generated integrations.

## Context Map

### Files to Modify

| File                                                             | Purpose                                 | Changes Needed                                                           |
| ---------------------------------------------------------------- | --------------------------------------- | ------------------------------------------------------------------------ |
| `crates/taskit-init/src/scaffold.rs`                             | Generates hooks, xtask, and CI workflow | Emit nested command paths and expose generated command fixtures to tests |
| `crates/taskit-init/src/render_cruxfile.rs`                      | Generates Crux shell steps              | Translate internal CI command IDs to public CLI paths                    |
| `crates/taskit-init/src/plan.rs`                                 | Carries inferred CI steps               | Keep internal dispatch IDs distinct from CLI reproduction commands       |
| `crates/taskit-init/tests/init_integration.rs`                   | Tests generated projects                | Assert generated commands are parseable and execute help-level parsing   |
| `src/main.rs`                                                    | Defines the clap command tree           | Provide test-only parsing conformance over generated command fixtures    |
| `xtask/src/main.rs`                                              | Checked-in delegation example           | Use current nested commands                                              |
| `Cruxfile`                                                       | Checked-in generated pipeline           | Use current nested commands                                              |
| Generated mdBook content in `crates/taskit-init/src/scaffold.rs` | Documents generated workflows           | Replace stale flat command examples through the same command mapping     |

### Dependencies

`taskit-init` cannot depend on the root binary. The root binary already depends on `taskit-init`, so conformance tests flow from a production command mapping into `Cli::try_parse_from` without a reverse dependency.

### Test Coverage

Update stale assertions in `scaffold.rs` and `render_cruxfile.rs`; strengthen `init_integration.rs`; add a table-driven parser test beside `Cli` in `src/main.rs`.

### Reference Patterns

Use the checked-in `.githooks/pre-commit`, `.githooks/pre-push`, and `.github/workflows/ci.yml` commands as valid nested-command examples.

## Crate Ownership

- **Generator crate**: `taskit-init` — owns rendered integration content.
- **CLI crate**: `taskit` — owns clap parsing and the conformance oracle.

## Public API

Add one small public command vocabulary in `taskit-init`; every renderer must consume it rather than maintaining command strings independently:

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum GeneratedCommand {
    SelfCheck,
    CheckFmt,
    CheckLint,
    CheckCompile,
    CheckDeps,
    TestRun,
    TestCoverage,
    ProtocolDrift,
    CheckCi,
    CheckPreCommit,
    CheckPrePush,
}

impl GeneratedCommand {
    pub const ALL: [GeneratedCommand; 11];
    pub fn argv(self) -> &'static [&'static str];
    pub fn shell(self) -> String;
}
```

Root tests prepend `taskit` to every `argv` value before clap parsing. Renderer tests assert their actual shell, Rust, YAML, mdBook, and Crux output contains values produced by `shell`, preventing a detached fixture list from passing while rendered output is stale.

## Data Flow

1. Init discovery produces logical CI step IDs such as `fmt --check` and `test`.
2. Renderers map each logical ID to a public path such as `check fmt --check` or `test run`.
3. Every renderer uses `GeneratedCommand`; tests inspect the actual rendered output rather than a duplicate command list.
4. The root clap parser accepts each invocation or fails the test.

## Hexagonal Boundaries

- **Port**: generated command vectors are the boundary between init renderers and the CLI parser.
- **Adapter**: each renderer converts a logical step into shell, Rust, YAML, or Crux syntax.

## Out of Scope

- A general JSON CLI schema.
- General documentation generation beyond correcting command examples in generated mdBook content.
- Changing internal `CiStep.cmd` identifiers.

## Risk

- [ ] Breaking API changes: additive public enum and methods in `taskit-init`.
- [ ] CLI behavior changes: generated integrations begin invoking the intended existing commands.
- [ ] New external dependency: no.
- [ ] Protocol lock update: no, unless production command definitions change.
