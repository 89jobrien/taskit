# xtask

`xtask` is the workspace-local task adapter generated by `taskit init`. It is a private Rust 2021
binary package with no Cargo dependencies and is not part of taskit's runtime dependency graph.

## Workspace role

The binary provides short names for common repository chores and delegates execution to taskit. It
first tries an installed `taskit` executable. If that cannot be spawned, it falls back to:

```bash
cargo run -p taskit -- <arguments>
```

The fallback only applies when spawning `taskit` fails. A taskit process that starts and exits with
an error is returned as an error; it is not retried through Cargo.

## Running it

This repository defines a `cargo taskit` alias, but it does not define a `cargo xtask` alias. Run
the package directly unless your environment supplies a separate `cargo-xtask` command:

```bash
cargo run -p xtask -- fmt
cargo run -p xtask -- ci
```

The accepted task names are:

| xtask name   | Arguments currently forwarded to `taskit` |
| ------------ | ----------------------------------------- |
| `fmt`        | `fmt`                                     |
| `fmt-check`  | `fmt --check`                             |
| `lint`       | `lint`                                    |
| `test`       | `test`                                    |
| `ci`         | `ci`                                      |
| `pre-commit` | `pre-commit`                              |
| `pre-push`   | `pre-push`                                |

Unknown names print the available list and exit with status 1. A delegated process failure is
propagated using its exit code, or status 1 when no code is available.

## Current implementation status

The adapter still forwards taskit's former flat command names. The current taskit CLI groups these
operations under `check` and `test`, for example `taskit check fmt --check`, `taskit test run`, and
`taskit check ci`. Consequently, the generated mappings above do not currently match the CLI and
will be rejected by the current parser. Treat this package as generated integration scaffolding,
not as the supported way to run repository checks, until its mappings are updated.

Use the current CLI directly instead:

```bash
cargo taskit check fmt --check
cargo taskit check lint
cargo taskit test run
cargo taskit check ci
cargo taskit check pre-commit
cargo taskit check pre-push
```

## Source layout

- `src/main.rs` owns unknown-task reporting and process exit behavior.
- `src/taskit/mod.rs` owns the generated mapping and binary/Cargo fallback.
- The sentinel comments in both files allow `taskit-init` to install or refresh managed sections
  without replacing unrelated user code.

The package has no Cargo features and no dedicated tests. Validate the current source with:

```bash
cargo check -p xtask
cargo fmt --all --check
```

Changes to the generated adapter should also be covered by the `taskit-init` scaffold tests:

```bash
cargo nextest run -p taskit-init
```
